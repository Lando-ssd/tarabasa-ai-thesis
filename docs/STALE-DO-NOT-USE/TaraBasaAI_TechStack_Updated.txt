------------------------------------------------------------
CURRICULUM GUIDE (clarified, not a new tech component)
------------------------------------------------------------
Built into the system as seeded reference data from the start — the
AI reads/matches against this data the same way it reads any other
reference table. It is NOT something Admin uploads or edits through a
UI form. If Admin needs to see it at all, that is a read-only
reference view, not a content-management feature. This keeps Admin's
actual responsibilities exactly where they were always meant to be:
account verification and status toggling only.

------------------------------------------------------------
WHY THIS REVISION IS FINE TO MAKE
------------------------------------------------------------
Revising one language, one API, or one supporting service after
further discussion does not break the rest of the system — the core
architecture (native mobile client + PHP/Laravel web+server + Cloud
SQL + Google Speech-to-Text) stays exactly the same, and every
business rule, data model, and workflow already specified across the
other prompts in this project is completely unaffected by this
change. Firebase here is additive infrastructure for notifications and
audio handling specifically, not a replacement for anything already
decided.
